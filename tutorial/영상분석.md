분석일: 2026-10-19. 최종 결과물은 요청에 따라 영상 모음 대신 `index.html`의 실행 가능한 HTML5 연습 화면이다. 9개 조작을 각각 고르거나 성공 후 “다음 조작”으로 이어서 연습할 수 있다. 원본 성공 장면 9개도 HTML 안에 포함했다.

## 1. 자료와 분석 범위

공유된 Google Drive 영상 4개를 다운로드했다. 전체 구간을 디코딩하여 초당 2프레임에서 버튼 이미지와 게이지를 탐색하고, 1분 간격 전체 흐름 화면과 검출 장면을 시각적으로 확인했다. 검출 구간은 원본 60fps로 다시 분석해 표시의 등장·소멸과 순서 변화를 확인했다. 모든 150분을 실시간으로 연속 시청한 방식은 아니다. 다른 형태의 매우 짧은 신호까지 없다고 단정하지 않는다.

영상은 PC 화면이며 손가락/키 입력 로그는 보이지 않는다. 따라서 **영상에서 보이는 신호·성공 변화**와 **저장소에서 검증한 입력 방식·판정 시간**을 구분했다. 최초 첨부된 `1019(...).mp4` 파일들과 Drive 파일이 동일하다고 가정하지 않았다.

## 3. 입력 판정과 태블릿 대응

`js/plugins/Synrec_QTE.js`의 `updateGauge`와 `updateCheckInput`을 확인했다. 첫 번째 표시와 같은 키의 `Input.isTriggered`를 한 번 감지하면 표시 하나가 사라진다. **한 번 누르고 손을 떼는 입력**이다. 길게 유지해도 반복 입력으로 세지 않으며, 같은 버튼을 다시 입력하려면 떼었다가 눌러야 한다. 방향 순서는 왼쪽 표시부터 처리한다. 표시가 뜨기 전에 미리 누르고 있는 것은 올바른 시범으로 사용하지 않았다.

방향키 연속 조작은 전체 목록이 한 제한 시간을 공유한다. 맞힐 때마다 시간이 새로 생기지 않는다. 단일 신호 5회는 각각 별도의 제한 시간이며, “신호 n/5 일치” 대사를 ●로 넘긴 뒤 다음 신호가 시작한다. 다른 키는 즉시 실패가 아니라 남은 시간 감점이다. 표시가 남아 있는데 시간이 끝나면 실패한다. 이번 영상에서는 확인 가능한 실패 QTE 표본을 확보하지 못했으므로 이 실패 규칙은 **코드 근거**다.

태블릿 버튼은 `js/plugins/DP_TouchControls.js`를 확인하고 원작을 Chromium 터치 환경으로 실행해 검증했다. ▲/◀/▶/▼는 up/left/right/down, **●는 ok(결정)**, ☰는 cancel이다. PC의 OK 아이콘을 태블릿에 새 OK 버튼으로 만들지 않았다. 원작과 같은 6개 버튼을 유지하되 ☰는 이번 정답 입력에 사용하지 않는다.

원작 게임의 가상 방향키로 방향 QTE 성공, ●를 400ms 유지했을 때 1회만 인정, 떼었다가 총 8회 누르면 연타 성공을 확인했다. 실제 물리 태블릿에서 직접 시험한 결과는 아니다.

버튼의 크기·모양·하단 기준 간격은 원작 설정을 따랐다. 안내 영역을 위해 게임 화면을 16:9 프레임에 넣었으므로 버튼은 **그 게임 프레임의 가장자리**를 기준으로 배치한다. 원작에서 브라우저 전체를 기준으로 배치되는 좌표와 절대 화면 좌표까지 같다는 뜻은 아니다.

## 4. 유형별 상황·자막·성공과 재시도


### 1. 수로를 점검해요

- 시작 상황: 정원에서 수로 점검을 시작할 때.
- 볼 곳: 화면의 청록색 표시, 그중 맨 왼쪽 표시와 위의 분홍 시간 막대. 단일 신호는 하나뿐인 화살표.
- 조작: 왼쪽 ◀ → 오른쪽 ▶ → 위 ▲. 길게 누르기나 동시 누르기를 요구하지 않음.
- 화면 상단의 실제 안내 자막: “표시가 뜨면 맨 왼쪽부터, 같은 방향키를 한 번 누르고 손을 떼세요.”
- 입력을 떼는 시점: 한 번 입력한 직후. 다음 같은 버튼을 누르기 전에 반드시 떼기. 400ms 유지 같은 특정 길이가 원작 조건인 것은 아님.
- 영상의 성공 변화: 화살표가 모두 사라지고 “물길을 끝까지 따라 확인했다.”가 나타남.
- 실패 조건: 시간 안에 남은 표시를 모두 없애지 못함. 다른 버튼은 위 표만큼 시간 차감. 실패 장면 자체는 이번 영상에서 확인되지 않음.
- 원작 재시도 처리(코드 확인): 실패 안내 뒤 이벤트가 끝남. 같은 수로 조사 이벤트를 다시 실행할 수 있는 구성. 영상의 실제 재시도 동작은 확인되지 않음.
- 내장 원본 클립: V3 18:23.9–18:27.9, 약 4.05초. 1배속, 무음, 960×540, 원본 16:9 유지.

## 5. 실제 구현한 장면과 강조 시간

연습은 고정 길이의 영상이 아니라 학생이 직접 진행하는 화면이다. 처음에는 해당 조작 제목과 목표 문장을 보이고, “천천히 따라 보기” 또는 “직접 연습하기”를 고른다. 자막과 시범만으로 진행하며 음성이 필요하지 않다.

1. **볼 곳 찾기:** QTE 직전 원본 정지 화면 위에 원작 표시 자산을 배치한다. 첫 표시를 노란 테두리와 “여기부터”로 강조한다. 전체 화면 비율을 유지하고 별도 확대·크롭하지 않는다.
2. **자동 시범 시작 0.00–0.90초:** “노란 테두리 안의 표시를 봐요.”를 표시한다. “천천히 보기 · 실제 제한 시간 아님”을 계속 표시한다.
3. **각 입력 시점:** 해당 버튼 중심에 손가락 그림과 밝은 테두리를 동시에 표시하고, “○○ 버튼을 한 번 톡 누르세요.” 자막과 함께 표시 하나를 지운다. 0.40초 후 손가락과 강조를 지우고 “손을 떼세요. 길게 눌러도 한 번만 세어요.”로 바꾼다. 0.40초는 시범을 읽기 위한 길이이며 원작의 요구 유지 시간이 아니다.
4. **다음 입력:** 일반 순서·연타는 첫 입력 0.90초부터 1.55초 간격으로 시범을 반복한다. 단일 신호는 정답 입력 뒤 1.05초에 “신호 n/5 일치” 카드와 ● 시범, 0.50초 뒤 ●를 떼고 카드를 닫으며 0.90초 뒤 다음 방향 입력을 시범 보인다.
5. **직접 연습:** 준비 카운트 뒤 신호와 게이지가 나타나며 시간이 시작한다. 준비 중 누른 손가락은 먼저 떼도록 안내한다. 정답은 표시 하나 삭제, 오답은 시간 차감과 올바른 버튼 안내, 오래 누르면 떼고 다시 누르라는 안내로 구분한다.
6. **성공:** “잘 맞혔어요!”와 유형별 성공 문구. “기억해요. 표시를 보고 → 한 번 누르고 → 손 떼기!”를 표시하고 “다시 연습하기 / 다음 조작”을 제공한다. 마지막 조작의 다음 버튼은 조작 선택으로 돌아간다.
7. **실제 장면:** “원작 장면 보기”는 위에 적은 클립을 원래 속도로 재생한다. 자동 시범을 원본 손가락 기록처럼 표시하지 않는다. 연습 성공 화면은 교육용 피드백이고 실제 원작의 성공 변화는 내장 클립으로 확인한다.
